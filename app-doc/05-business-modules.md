# Business Modules

## CRM

**Leads** (`/leads`) — a prospect, with a `source` (Google, Referral, Walk-in, …, managed under Lead Sources), a `stage` (a company-configurable pipeline stage, e.g. New → Contacted → Quotation Sent → Won/Lost), an `assignee`, an `estimated_value`, and a `status` of `open | won | lost`. A lead can be **converted to a customer** (`POST /leads/{lead}/convert-to-customer`), which creates a `Customer` row and marks the lead `won`.

**Customers** (`/customers`) — individual or company accounts. Each can have multiple `CustomerContact` rows (for company-type customers with several contact people), a credit limit, payment terms, and rolls up its own quotations/invoices/payments/activities on its detail page.

**Activities** — a polymorphic log (call, meeting, email, WhatsApp, note, follow-up) attachable to a Lead or Customer, shown as a tabbed "Log Activity / Timeline" widget (`ActivityFeed` component) on both detail pages.

## Sales

The core document flow is **Quotation → Invoice → Payment**:

1. **Quotations** (`/quotations`) — line items priced from `Items` (or free-text), with per-line and document-level discount/tax. Status lifecycle: `draft → sent → viewed → accepted | rejected`, or `expired` if `valid_until` passes unaccepted. An accepted quotation can be **converted to an invoice** (`POST /quotations/{quotation}/convert-to-invoice`), copying all line items over.
2. **Invoices** (`/invoices`) — same line-item structure as quotations, plus a `due_date`. Status: `draft → sent → partially_paid | paid`, or `overdue` (computed from `due_date` vs. today, not a stored transition), or `cancelled`.
3. **Payments** (`/payments`) — a payment is recorded against a customer and then *allocated* across one or more of their open invoices (`PaymentAllocation`). `InvoiceBalance` support class recalculates each invoice's `paid_amount`/`balance_amount`/status whenever an allocation changes.

Both quotations and invoices can be downloaded/viewed as PDF (`GET /quotations/{id}/pdf`, `GET /invoices/{id}/pdf}`) via `PdfDocumentData` + `barryvdh/laravel-dompdf`. Document numbers (`QUO-2026-00001`, `INV-2026-00001`) are sequential per company per year, generated by `App\Support\NumberGenerator`.

**Term Templates** — reusable "terms & conditions" blocks an owner/admin can define once and pick from when creating a quotation/invoice.

## Products & Services

**Items** (`/items`) — the catalog quotations/invoices pull line items from: name, SKU, unit price, default tax rate, and a `Unit` (pieces, kg, hours, …). Units and Payment Methods follow the same pattern: platform-wide defaults plus per-company custom entries, managed inline from the Items/Payments pages respectively rather than as their own top-level nav item.

## Expenses

**Expenses** (`/expenses`) — company spending, categorized (`ExpenseCategory`, company-managed), with a vendor, amount, tax, and optional receipt attachment. Feeds directly into the Expense Report and the VAT Summary's input-VAT side.

## Reports

Reports (`/reports/*`) is a **parent nav module** with five child pages, each hitting its own `ReportController` endpoint via `ReportService`:

| Page | Endpoint | What it shows |
|---|---|---|
| Sales Report | `GET /reports/sales` | Invoiced/paid/outstanding totals + invoice list, for a date range |
| Expense Report | `GET /reports/expenses` | Spend by category + expense list, for a date range (optionally filtered to one category) |
| Aging / Outstanding | `GET /reports/aging` | Unpaid invoice balances bucketed into Current / 1-30 / 31-60 / 61-90 / 90+ days overdue |
| VAT Summary | `GET /reports/vat` | Output VAT (from sales) vs. input VAT (from expenses) vs. net payable, by month, for a date range |
| Customer Statement | `GET /reports/customer-statement` | Running ledger (opening balance → invoices/payments → closing balance) for one selected customer |

Access is restricted server-side to `owner|admin|accountant|demo` roles (`routes/api.php`), independent of the menu-permission system used elsewhere, since these expose the company's financials directly.

Each report page fetches its whole (already date-filtered) dataset in one request rather than a paginated resource, then renders its table with `ReportTable` — a client-side-only counterpart to the app's `ServerDataTable` (same look: search, sortable headers, pagination), since re-sorting/paging an already-loaded small dataset locally is both simpler and faster than round-tripping to the server for it.

## Attachments (cross-cutting)

Files can be attached to Customers, Leads, Quotations, Invoices, and Expenses via one polymorphic `Attachment` model and a shared `AttachmentPanel` frontend component, rather than a separate uploads table per entity.
